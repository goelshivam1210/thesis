\section{Formal Framework for Executor Discovery}
\label{sec:ipt}

\rev{Having described the neurosymbolic architecture at a component level, we now formalize the adaptation problem that \RAPidLearn{} is designed to solve.} This section extends the integrated planning task (IPT) formalism developed in \cref{sec:hybrid} to characterize adaptation under novelty. The IPT $\IPT = \langle \PlanningTask, M, \Abstraction, e \rangle$ couples symbolic planning with subsymbolic execution through the detector $\Abstraction$ and the executor mapping $e$. In open-world settings, this correspondence can break: novelty may render an executor invalid, creating a gap between what the symbolic model prescribes and what the agent can actually execute. We extend the operator--executor accuracy conditions from \cref{sec:hybrid} and define the \emph{executor discovery problem} as the core challenge of adaptation when executors fail under obstructive novelty.


\subsection{Executors}
\label{sec:executors}

\Cref{sec:hybrid,sec:rl} introduced executors as the mechanism connecting symbolic operators to environment interaction. We restate the definition here to establish the notation used throughout this chapter.

\begin{definition}[Executor]
\label{def:executor}
An executor $\Executor = \langle I_{\Executor}, \Policy_{\Executor}, \beta_{\Executor} \rangle$ consists of:
\begin{itemize}[leftmargin=*]
    \item An \emph{initiation set} $I_{\Executor} \subseteq \States$, the set of environment states in which the executor can be initiated.
    \item An \emph{intra-executor policy} $\Policy_{\Executor}(a \mid s_0, s)$, which defines a probability distribution over actions $a \in \Actions$ given initiation state $s_0 \in \States$ and current state $s \in \States$.
    \item A \emph{termination condition} $\beta_{\Executor} : \States \times \States \rightarrow \{0, 1\}$, where $\beta_{\Executor}(s_0, s) = 1$ if the executor terminates in state $s$ given that it was initiated in state $s_0$, and $0$ otherwise.
\end{itemize}
\end{definition}

Let $\Executors = \{\Executor_1, \Executor_2, \ldots\}$ denote the set of all available executors. Executors may be hand-coded, learned through reinforcement learning, or implemented by internal planners (e.g., a navigation policy that computes paths using $A^*$).

\subsection{Integrated Planning Task}
\label{sec:ipt_def}

\begin{definition}[Integrated Planning Task]
\label{def:ipt}
An integrated planning task (IPT) is a tuple $\IPT = \langle \PlanningTask, M, \Abstraction, e \rangle$ as defined in \cref{sec:hybrid}, where $\PlanningTask = \langle \PlanningDomain, \SymState_0, \Goal \rangle$ is a symbolic planning task (\cref{sec:symbolic_planning}), $M = \langle \States, \Actions, \Transition, \Reward, \Discount \rangle$ is a Markov decision process (\cref{sec:rl}), $\Abstraction : \States \rightarrow \SymStates$ is a detector mapping subsymbolic states to symbolic states, and $e : \Operators \rightarrow \Executors$ is an executor mapping.
\end{definition}

An IPT is well-formed when each $e(\Operator)$ is accurate to $\Operator$ as defined in \cref{sec:hybrid}. The termination condition is extended below for open-world execution.

\paragraph{Consistency between operators and executors.}
For an IPT to function correctly, each executor must be consistent with the symbolic specification of its corresponding operator (\cref{sec:symbolic_planning}). Let $\Operator \in \Operators$ have precondition literal set $\Pre_{\Operator}$ and effect literal set $\Eff_{\Operator}$. The executor $e(\Operator)$ must satisfy:

\begin{enumerate}[leftmargin=*]
    \item \emph{Initiation consistency}:
    \[
    I_{e(\Operator)} \supseteq \{ s \in \States : \Abstraction(s) \models \Pre_{\Operator} \}.
    \]
    In other words, the condition above says that the executor can begin execution if the operator's preconditions are satisfied.

    \item \emph{Termination consistency}: The executor terminates either when the operator's effects are achieved or when sufficient progress has been made to continue planning:
    \[
    \beta_{e(\Operator_i)}(s_0, s) = 
    \begin{cases}
        1 & \text{if } \Abstraction(s) \models \Eff_{\Operator_i}, \\
        1 & \text{if } \Abstraction(s) \models \Eff_{\hat{\Operator}} \ \forall \hat{\Operator} \in \hat{\Operators} \ \text{and } \exists \hat{\Plan} \text{ from } \Abstraction(s) \text{ to } \Goal, \\
        0 & \text{otherwise},
    \end{cases}
    \]
    where $\hat{\Operators} = \{\Operator_j \in \Plan : j > i \land \Operator_i \Dep \Operator_j\}$ denotes subsequent operators in the plan that depend on the effects of $\Operator_i$ (\cref{sec:symbolic_planning}).
\end{enumerate}

The first case corresponds to exact satisfaction of the operator’s effects. The second allows progress beyond the current operator if downstream effects are satisfied and a valid plan to the goal still exists. In other words, once the executor reaches a plannable state, it can be terminated. Later, we will formalize and explain how the plannable states are generated.

\paragraph{Solutions to an IPT.}
A \emph{planning solution} to an IPT is a plan $\Plan = [\Operator_1, \ldots, \Operator_n]$ that solves $\PlanningTask$. A \emph{solution} is the corresponding sequence of executors $[e(\Operator_1), \ldots, e(\Operator_n)]$ such that executing them in the environment from an initial state $s_0$ with $\Abstraction(s_0) = \SymState_0$ yields a state $s'$ with $\Abstraction(s') \models \Goal$. An IPT is \emph{plannable} if a planning solution exists and \emph{solvable} if a solution exists.

\subsection{The Executor Discovery Problem}
\label{sec:executor_discovery}

In closed-world settings, every operator has a valid executor, and a plannable IPT is also solvable (\cref{sec:hybrid}). In open-world environments, novelty can break this correspondence: an executor may fail because the environment dynamics no longer match the operator's modeled effects. When operator--executor correspondence breaks while the symbolic plan remains valid, the IPT remains plannable but is no longer solvable (\cref{sec:novelty_hybrid,def:obstructive}).

\begin{definition}[Stretch-IPT]
\label{def:stretch_ipt}
A \emph{stretch-IPT} $\tilde{\IPT}$ is an IPT $\IPT = \langle \PlanningTask', M', \Abstraction, e \rangle$ whose planning task $\PlanningTask'$ incorporates novelty, for which a planning solution exists but the current executor mapping $e$ does not yield an execution solution~\citep{goel2022rapidlearn}.
\end{definition}

Using the novelty formalism from \cref{sec:novelty}, a novelty introduces elements not captured by the current model. When an operator $\Operator_i$ fails during execution---that is, $e(\Operator_i)$ does not produce a state satisfying $\Eff_{\Operator_i}$---the agent faces a stretch-IPT and must discover a new executor for $\Operator_i$ while preserving the existing symbolic plan structure.

\begin{definition}[Executor Discovery Problem]
\label{def:edp}
Given a stretch-IPT $\tilde{\IPT} = \langle \PlanningTask', M', \Abstraction, e' \rangle$ with $\PlanningTask' = \langle \PlanningDomain', \SymState_0', \Goal \rangle$, where $\PlanningDomain' = \langle \Fluents \cup \Fluents', \Operators \cup \Operators' \rangle$, and failed operators $\{\Operator_1, \ldots, \Operator_m\}$, construct new executors $\{\Executor'_1, \ldots, \Executor'_m\}$ such that
\[
e'(\Operator_i) = \Executor'_i
\]
for each failed operator $\Operator_i$, making $\tilde{\IPT}$ solvable.
\end{definition}

The executor discovery problem captures the essence of adaptation under novelty: the agent must acquire new low-level behaviors that realize high-level operator specifications in a changed environment. This cannot be achieved through symbolic reasoning alone, as the model is incomplete, nor through unguided learning, as exhaustive exploration is inefficient. Instead, the agent must leverage its symbolic structure to guide the learning of new executors. The next section presents \RAPidLearn{}, which addresses this problem by instantiating focused reinforcement learning problems for failed operators, guided by existing domain knowledge.
