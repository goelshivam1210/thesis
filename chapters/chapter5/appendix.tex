\subsection{Agent Implementation}
\label{sec:ch5_agent_implementation}

\rev{For all evaluations, a domain-interface component parses the environment's sensory information (Polycraft provides it in JSON) into the first-order predicate form used by the rest of the architecture; the same interface works with NovelGridworlds. The knowledge base $\KB$ is implemented as a set of Prolog facts and rules, queried whenever the truth value of a fact is needed (e.g.,\ when checking preconditions and effects). Operators are written in an Action Script Language (ASL). During planning, the Prolog facts and ASL operators are translated into a PDDL problem and domain and solved with the off-the-shelf MetricFF planner~\citep{hoffmann2003metricff}; only operators with at least one known effect are exported to the planner.}

\rev{The time budget for any one exploration strategy is domain-specific. In Polycraft, where the agent is evaluated against a time-out, phases such as knowledge discovery are given a fixed budget, because they run before the agent even plans for the main goal. The symbolic operator-discovery strategies are similarly bounded; for example, precondition discovery in Polycraft focuses only on variations of the \texttt{holding(self,X)} predicate for novel objects $X$, since this predicate is a prominent state aspect in the domain. Reinforcement-learning-based exploration is the exception: as the final strategy invoked after all others fail, it is allowed to continue until the environment times out.}

\rev{Which strategies are attempted in the total-effect-failure policy also depends on the failed operator. Strategy~1 (update effects and replan) is skipped for movement operators, since deleting their effects could destroy the agent's ability to move; instead, repeated execution (Strategy~2) is preferred, on the assumption that the knowledge base is merely inaccurate. Precondition discovery and operator variation are excluded for operators with more than one parameter to avoid an excessively large search space. These heuristics are effective in Polycraft but are not necessarily portable to other domains.}

\subsection{Simulation and Compute}
\label{sec:ch6_compute}

\rev{The systemic evaluations were run on the LoneStar6 cluster at the Texas Advanced Computing Center. Neural models in the integrated architecture were trained on a server with four NVIDIA RTX 2080Ti GPUs and an Intel Core i9-9940X processor with 130\,GB of memory. The non-novelty-aware reference agent is a simple PDDL-based planning agent integrated with the Polycraft domain.}

\subsection{Domain PDDL}
\label{sec:ch6_domain_pddl}

\rev{Below is the original PDDL domain given to RAPid-Learn for the pogostick-crafting task inspired by Minecraft in NovelGridworlds.}

\begin{lstlisting}[
  style=pddlstyle,
  caption={Domain PDDL for the pogostick-crafting task.},
  label={lst:pogostick-domain-pddl}
]
(:requirements :typing :strips :fluents)
(:types
    wall - physobj
    entity - physobj
    plank - physobj
    crafting_table - physobj
    tree_tap - physobj
    var - object
    rubber - physobj
    physobj - physical
    actor - physical
    pogo_stick - physobj
    stick - physobj
    tree_log - physobj
    air - physobj
)

(:predicates
    (holding ?v0 - physobj)
    (floating ?v0 - physobj)
    (facing ?v0 - physobj)
)

(:functions
    (world ?v0 - object)
    (inventory ?v0 - object)
)

(:action approach
    :parameters    (?physobj01 - physobj ?physobj02 - physobj )
    :precondition  (and
        (>= ( world ?physobj02) 1)
        (facing ?physobj01)
    )
    :effect  (and
        (facing ?physobj02)
        (not (facing ?physobj01))
    )
)

(:action crafttree_tap ; 
    :parameters    ()
    :precondition  (and
        (>= ( inventory plank) 4)
        (>= ( inventory stick) 1)
        (facing crafting_table)
    )
    :effect  (and
        (increase ( inventory tree_tap) 1)
        (decrease ( inventory plank) 5)
        (decrease ( inventory stick) 1)
    )
)

(:action craftplank
    :parameters    ()
    :precondition  (>= ( inventory tree_log) 1)
    :effect  (and
        (increase ( inventory plank) 4)
        (decrease ( inventory tree_log) 1)
    )
)

(:action break
    :parameters    ()
    :precondition  (and
        (facing tree_log)
        (not (floating tree_log))
    )
    :effect  (and
        (facing air)
        (not (facing tree_log))
        (increase ( inventory tree_log) 1)
        (increase ( world air) 1)
        (decrease ( world tree_log) 1)
    )
)

(:action craftstick
    :parameters    ()
    :precondition  (>= ( inventory plank) 2)
    :effect  (and
        (increase ( inventory stick) 4)
        (decrease ( inventory plank) 2)
    )
)

(:action extractrubber
    :parameters    ()
    :precondition  (and
        (>= ( inventory tree_tap) 1)
        (facing tree_log)
        (holding tree_tap)
    )
    :effect  (and
        (increase ( inventory rubber) 1)
    )
)

(:action craftpogo_stick
    :parameters    ()
    :precondition  (and
        (>= ( inventory plank) 2)
        (>= ( inventory stick) 4)
        (>= ( inventory rubber) 1)
        (facing crafting_table)
    )
    :effect  (and
        (increase ( inventory pogo_stick) 1)
        (decrease ( inventory plank) 2)
        (decrease ( inventory stick) 4)
        (decrease ( inventory rubber) 1)
    )
)

(:action select
    :parameters    (?physobj01 - physobj )
    :precondition  (and
        (>= ( inventory ?physobj01) 1)
        ; (holding air)
    )
    :effect  (and
        (holding ?physobj01)
        (not (holding air))
    )
)

)
\end{lstlisting}
